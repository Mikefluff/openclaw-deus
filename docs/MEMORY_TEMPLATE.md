# MEMORY_TEMPLATE.md

## Purpose

Define the canonical schema for daily DEUS memory files.

This document is the human-readable contract for the same daily-memory shape enforced in `src/memory/daily-memory-schema.js` and consumed by `src/memory/deus-memory-file-store.js`.

---

## Canonical structure

```markdown
# YYYY-MM-DD — DEUS Activity Log

**Total activities:** N

## Git Activity
- commits, branches, repo-changing git operations

## Commands Executed
- important commands worth remembering at the day-log layer

## Decisions
- decisions, rationale, structural choices, policy changes

## Interactions with Human
- relevant human interactions or instructions that affect continuity

## System Events
- runtime or operational events that matter for later reconstruction

---
*Auto-generated by DEUS memory manager*
```

---

## Writing rules

### Include
- consequential git activity
- meaningful commands worth retaining above raw logs
- decisions and their rationale
- user interactions that matter for continuity
- system events that help reconstruct the day

### Avoid
- low-level procedural spam already captured in `logs/*.jsonl`
- placeholder bullets with no content
- alternative section names outside the canonical contract
- reflective/introspective prose that belongs in `docs/introspection/`

---

## Relationship to other layers

- `logs/` = machine-oriented daily activity stream
- `docs/introspection/` = reflective system reports
- `memory/` = readable episodic continuity using the canonical section contract above
- `beliefs/` = durable semantic state

Daily memory is the bridge between operational traces and later semantic stabilization.
