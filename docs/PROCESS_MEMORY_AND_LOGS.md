# PROCESS_MEMORY_AND_LOGS.md

## Purpose

Clarify the roles of `memory/`, `logs/`, and `docs/introspection/` in the current DEUS workspace, and record the removal of the former `journal/` layer.

---

## Current State

### `memory/`
Role:
- episodic memory
- daily event-oriented continuity
- user-visible or cognition-relevant day logs

Formation:
- created by `src/memory/deus-memory.js`
- follows the canonical structure documented in `docs/MEMORY_TEMPLATE.md`
- enriched/generated by `scripts/aggregate-logs.js`
- reviewed by `scripts/introspection.js`
- can be augmented by nightly memory consolidation with an agent-level reflection block

### `logs/`
Role:
- canonical daily DEUS activity log
- the source for memory reconstruction into `memory/YYYY-MM-DD.md`

Formation:
- generated by `scripts/deus-logger.js`
- stored as `logs/YYYY-MM-DD.jsonl`
- consumed by `scripts/aggregate-logs.js`

### `.tmp/diagnostics/deus/ops/`
Role:
- low-level operational diagnostics
- machine-oriented traces for extraction, decay, contradictions, validation, integration

Formation:
- generated by component-level runtime helpers such as:
  - `scripts/belief-decay.js`
  - `scripts/belief-extractor.js`
  - `scripts/belief-contradictions.js`
  - `scripts/belief-promotion-review.js`
  - `scripts/openclaw-integration.js`

### `docs/introspection/`
Role:
- structured introspection reports
- higher-level self-review artifacts
- summaries of coherence and system health

Formation:
- generated by `scripts/introspection.js`

## Timezone Contract

- Canonical workspace-local timezone is resolved by the independent locality layer.
- Resolution order: `WORKSPACE_TZ` -> `USER.md` timezone -> default `UTC`.
- Daily file names such as `memory/YYYY-MM-DD.md` and `logs/YYYY-MM-DD.jsonl` must use the workspace-local day key, not the UTC calendar date
- Local time-only values written into memory entries should use the workspace-local clock
- Raw ISO timestamps may still remain in operational payloads and reports when exact machine time is required

## Conclusion

Current effective model is:
- `memory/` = episodic memory
- `logs/` = canonical daily DEUS activity history
- `.tmp/diagnostics/deus/ops/` = operational diagnostics
- `docs/introspection/` = reflective reports

The former `journal/` layer has been removed because it duplicated introspection responsibilities without being the active runtime sink.

---

## Working Recommendation

1. Keep `memory/` as episodic memory.
2. Keep `logs/` reserved for the daily canonical activity stream.
3. Keep `.tmp/diagnostics/deus/ops/` for noisy runtime diagnostics.
4. Keep `docs/introspection/` as canonical introspection output.
5. Do not reintroduce a parallel reflection sink unless it has a clearly distinct purpose.
